After a new modification is saved..
    1. git add: to copy the file from the working directory to the git staging area.
    2. git commit: to move the git staging area to the git local repository (repo).
    3. git push: to copy the git local repo to the GitHub remote repo.

After commiting, the staging area is NOT emptied.

Imagine now, that the file has been deleted by accident. How can I restore a 
copy of the file, either from the 1.staging area, 2.the local repo and 3.the remote repo.

1.From the staging area: 
    git restore --staged <file>  to delete the staged reference.
    git restore <file>  to revert changes in te working file.

2.From the local repo: git reset --mixed/soft/hard #commitid
    where the #commitid can be obtained from: git log --oneline
    [git reset] comes wit three options: soft, hard, mixed.
    [mixed] (default): removes commit and keep changes is working area.
    [soft]: removes commit and keep changes is staging area.
    [hard]: removes commit and discard changes in working and staging area.

3.From the remote repo: git reset --hard origin/main
    It replaces files and git history !!

Also [git revert], reverts changes in the current (lastest?) commit.

To reset the remote repo to a previous commit:
    1. Reset the local repo ex:  git reset --hard 5bada76
    2. Reset the remote repo ex: git push origin +5bada76:main  (where + is to force the push)
